# 测试与验收边界

## 自动化测试

提交与 Pull Request 会执行：

- `npm ci`：锁文件一致性；
- `npm run typecheck`：TypeScript 静态检查；
- `npm test -- --runInBand`：日期、目标体重与备份路径安全逻辑；
- `./gradlew assembleDebug`：在不提供 Release 密钥的干净环境完成 Android 编译。

## v1.0.1 已执行的模拟器端到端范围

- 首次启动与新建多只宠物；切换后验证提醒、健康、成长、照片与附件隔离；
- 每只宠物 1–5 张照片、相机/系统照片选择器、主图切换与删除；
- 疫苗、驱虫、用药、体检提醒的新增、编辑、完成、稍后、跳过和周期联动；
- 体重/健康记录、成长时间轴、附件和回收站；
- 通知授权允许/拒绝与本地测试通知；
- 杀进程重开、模拟器重启、飞行模式；
- 完整备份、修改数据、恢复并校验数据库/照片/附件；
- 卸载重装后从备份恢复；
- Release APK 安装、启动、版本和签名检查。

## 未宣称通过的范围

真实品牌手机上的厂商通知策略、文件管理器差异、相机兼容性、低存储空间、系统升级和长期定时可靠性仍需在目标设备验证。贡献者和发布者必须把“模拟器已通过”与“真机已通过”分开记录，不得用静态检查代替真实交互证据。

## 手工回归建议

发布前至少在一台目标 Android 手机上完成：全新安装、权限拒绝后继续使用、拍照/选图、通知、重启、飞行模式、完整备份、卸载重装和恢复，并保存系统版本、机型、APK SHA-256 和结果。
